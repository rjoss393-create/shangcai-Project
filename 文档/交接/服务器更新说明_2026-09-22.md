## 0. 一句话概括

本次更新包含三件事：

1. **知识星系换引擎**：从旧的四层星系换成 **v12 统一知识星系**（31,429 节点 / 55,997 边 / 六层钻取），后端新增 `graph_id=v12`（同时保留 `v6`）。

3. **修掉首页指数不显示**：`index.html` 里 Chart.js 由**外链 CDN 改为本地文件** `js/chart.min.js`。这是本次最关键的一处修复，详见第 2.3 节。

**不需要 `pip install`**：`requirements.txt` 与上一版逐字节相同。

## 1. 压缩包怎么用

- 包内**按原目录结构**保存了「新增」与「有改动」的文件（相对项目根目录的路径与服务器上一致）。
- 用法：**解压后整体覆盖到服务器项目根目录**，保留目录结构（不要把文件挑出来手拷，以免漏掉新目录）。
- 包内附 `更新清单.txt`：逐文件列出「新增/替换」、体积、SHA256，可用它核对覆盖结果。
- 包内附 `更新说明.md`：本文件的副本。

包内**不含**下列内容（都不需要更新，也不用重传）：

| 未包含 | 原因 |
|---|---|
| `.git/`、`.workbuddy/` | 版本库/本地工作目录，与运行无关 |
| `数据/`（约 4.8GB） | 原始交付素材，gitignore，不进任何交付包 |
| `data/media/videos/`、`papers/`、`books/`、`videos.json` | 与上一版**逐字节相同**，无需重传（唯一新增的媒体文件是 `data/media/courses.json`，已在包内） |
| `backend/cache/` | 运行期 embedding 缓存，服务器上会自动重建 |
| `前端/proxy-server/node_modules/` | 本地依赖，服务器不需要 |
| `文档/交接/*` | 这些是发给**前端负责人**的对接文档，与服务器部署无关 |

> ### ⚠️ 本次最关键的一处修复：Chart.js 必须走本地文件
>
> 上一版 `index.html` 用的是外链：
> ```html
> <script src="https://cdn.jsdelivr.net/npm/chart.js"></script>
> ```
> 该 CDN 在国内网络经常 `ERR_CONNECTION_RESET` 拉不到 → `window.Chart` 未定义 →
> `js/main.js` 的 `initChart()` 抛 `ReferenceError`。而 `initChart()` 是 `DOMContentLoaded` 回调的**第一条语句**，
> 一抛错，后面 `setupStockTabs / startRealtimeLoop / loadNewsFromApi` **全部不执行** →
> 首页表现为**指数表 0 行、走势图区域空白**（图表 canvas 只有 300×150 的默认空白）。
>
> 请确保更新后 `index.html` 引用的是 `js/chart.min.js`（包内已带），并且
> `curl -o /dev/null -w '%{http_code}' http://<服务器>:8000/js/chart.min.js` 返回 **200**。

```

4) 确认这三个新数据文件已就位：
     data/layered/v12_layered.json    25,283,212 字节
     data/layered/v6_layered.json      3,139,081 字节
     data/media/courses.json              20,840 字节
   （用 更新清单.txt 里的 SHA256 可逐文件校验）
5) 启动后端：
     Windows：  E:/python/python.exe -m uvicorn main:app --host 0.0.0.0 --port 8000
     Linux：    python -m uvicorn main:app --host 0.0.0.0 --port 8000
6) 看启动日志，等到出现「[preload] xxx 预热完成」共 6 行：
     ma / corp_fin / intl_inv / invest / econ / v6
   （v12 的预热行在 v6 之后，首次会明显慢一些）
```

### 首次启动耗时与内存提示

- **v12 首次预热：建图约 40 秒 + embedding 约 35 秒（一次性）**，之后走
  `backend/cache/v12_all-MiniLM-L6-v2/` 命中缓存，秒级完成。
- 预热在**后台任务**里做，所以这期间**页面可以正常打开**，只是知识星系板块要等预热完才有点击/问答响应。
- 若服务器内存偏紧，想只保留一个星系：把 `backend/controller/graph_ids.py` 里的 `"v12": ...` 一行
  与 `backend/service/data_service.py` 里对应的 `"v12": "layered/v12_layered.json"` 一行删掉，重启即生效
  （此时前端 `knowledge-galaxy.js` 若走 API 会拿不到 v12 数据，需配合 `data/galaxy_v12.json` 本地兜底或改回 v6；**默认不建议这么做**）。

### 本次不需要清缓存

`v6`/`v12` 是**全新**的 graph_id，服务器上原本不存在它们的 embedding 缓存，所以**不需要**删
`backend/cache/`。只有在「同一个 graph_id 的数据被替换」时才需要删
`backend/cache/<graph_id>_all-MiniLM-L6-v2/` 再重启。
