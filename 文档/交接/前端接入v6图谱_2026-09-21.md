> ⚠️ **本文件是改动前的方案稿，已于 2026-09-21 按此执行完毕。**
> 实际改动记录 + **对接约定（发给前端以后照此更新）** 见
> **`文档/交接/前端v6接入说明与约定_2026-09-21.md`**。本文件留作评审记录。

> 前提：后端已把 v6 注册成 `graph_id`（`load`/`click`/`query` 全部可用，自测见
> `文档/记录/v6图谱接入后端记录.md`）。本文只讲**前端要改哪里**。
>

## 一、先说清楚"接入"到底要解决什么

页面上有两条彼此独立的链路：

| | 数据来源 | 节点 id |
|---|---|---|
| **画布显示** | `knowledge-galaxy.js` → `fetch('data/galaxy_v6_clustered.json')`（本地文件） | `kp_*` |
| **助手问答** | `assistant.js` → `POST /api/graph/query { graph_id }` → 后端按 graph_id 取图 | `concept_*` / `section_*`（现为 econ） |

两条链路现在**各走各的**，于是：

1. 助手问出来的答案引用的是 econ 图谱的 `concept_*` 节点；
2. 画布上画的是 v6 的 `kp_*` 节点；
3. `assistant.js` 拿到引用后调 `GalaxyEngine.pulseNodes(ids)` 高亮 —— **找不到节点，高亮全失效**，
   而且答案正文讲的是 econ 那张图的内容，跟眼前这张图对不上。

**根因**：新引擎的 `state` 里只有 `currentGraphId`，**没有 `graphId`**；
而 `assistant.js` 读的是 `state.graphId`（`前端/SUFE-Knowledge-Galaxy/js/assistant.js` 第 35 行
`graph_id: state.graphId || 'econ'`）→ 取不到就恒为 `'econ'`。

## 二、四处改动（文件均在新包里的相对路径，合并后落在 `前端/SUFE-Knowledge-Galaxy/`）

### ★ 改动 1（必须，1 行）：让助手拿到正确的 `graph_id`

文件 `js/knowledge-galaxy.js`，`state` 定义处（新包第 56~57 行）：

```js
        sessionId: null,
        currentGraphId: 'econ',   /* 兼容旧引擎契约（课程星系移植时读写） */
```

改为：

```js
        sessionId: null,
        currentGraphId: 'econ',   /* 兼容旧引擎契约（课程星系移植时读写） */
        graphId: 'v6',            /* ★ 知识星系画布显示的永远是后端的 v6 图谱，助手按此提问 */
```

> ⚠️ **不要**写成 `graphId` 到 `currentGraphId` 的别名（getter）。
> `js/course-galaxy.js` 在从课程星系跳转时会调 `switchGraph('econ')` / `switchGraph(gid)`
> （第 554、723、740 行），会把 `currentGraphId` 改写成书图 id，
> 而画布显示的**始终是 v6** —— 别名会让问答重新跑偏。
> 旧引擎那份别名（`前端/.../js/galaxy.js` 第 119~124 行 `Object.defineProperty(state,'graphId',…)`）
> 在这里**不能照搬**。

### ★ 改动 2（推荐）：取数改走后端，避免两份 v6 数据

文件 `js/knowledge-galaxy.js`，`load()`（新包第 346~353 行）。

顶部加一个常量（挨着第 25 行的 `DATA_URL`）：

```js
    const GRAPH_ID = 'v6';   /* 后端已登记的统一知识星系 */
```

`load()` 改前：

```js
        loadPromise = fetch(DATA_URL)
            .then(r => { if (!r.ok) throw new Error('HTTP ' + r.status); return r.json(); })
            .then(data => {
                state.data = data;
```

改后：

```js
        loadPromise = fetch('/api/graph/load', {
                method:  'POST',
                headers: { 'Content-Type': 'application/json' },
                body:    JSON.stringify({ graph_id: GRAPH_ID })
            })
            .then(r => { if (!r.ok) throw new Error('HTTP ' + r.status); return r.json(); })
            .then(resp => {
                if (!resp || resp.code !== 0) throw new Error((resp && resp.message) || '接口异常');
                const d = resp.data || {};
                /* 后端契约 {id,label,page,layer,media,extra} -> v6 引擎原字段名。
                   v6 的原始字段（level/parent_id/content/cluster_id/domain/tags/…）
                   全部原样保留在 extra 里，所以这里一行就能还原。 */
                const data = {
                    nodes: (d.nodes || []).map(n =>
                        Object.assign({}, n.extra || {}, { id: n.id, name: n.label })),
                    edges: (d.edges || []).map(e =>
                        Object.assign({}, e.extra || {}, {
                            source: e.source, target: e.target, relation: e.relation
                        }))
                };
                state.data = data;
```

后面（`state.idx = buildIndex(data)` 起的十余行）**一个字都不用改**。
`DATA_URL` 变成无用常量，删掉或留作注释都行。

> **不做这一步的替代方案**：把 `data/galaxy_v6_clustered.json`（4.7 MB）原样放进前端 `data/` 目录，
> 显示部分零改动。代价是同一份 v6 数据存两份（前端 4.7 MB + 后端 3.0 MB）且日后容易改跑偏；
> 而且**改动 1 仍然省不掉**（提问的 `graph_id` 还是错的）。所以推荐走后端。

### ★ 改动 3（建议）：补齐与新引擎对不上的兼容层

`js/course-galaxy.js` 从课程星系跳知识星系时用的是旧引擎的接口
（新包第 544~545 行）：

```js
            if (eng.state.nodes?.some(n => n.id === kpId)) {
                eng.clickNode(kpId);
```

但新引擎的 `state` 里节点在 `state.data.nodes`（索引在 `state.idx`），**没有 `state.nodes`**，
`window.GalaxyEngine` 也**没有 `clickNode`** → 跳过去只会反复重试然后 toast「未找到对应概念节点」。

文件 `js/knowledge-galaxy.js`：
① `state` 定义之后（就在 `};` 那行下面）补一个别名：

```js
    /* 课程星系跳转兼容：旧引擎的 state.nodes */
    Object.defineProperty(state, 'nodes', {
        get()  { return (state.data && state.data.nodes) || []; },
        enumerable: true, configurable: true
    });
```

② `window.GalaxyEngine` 里补 `clickNode`（挨着 `selectNode`）：

```js
        clickNode(idOrName) { this.selectNode(idOrName); },
```

> 这是新包自带的一处对不上（他们换了引擎内部结构，但 `course-galaxy.js` 还在用旧接口），
> 不是我们引入的。补上之后「课程星系点概念 → 跳到知识星系并聚焦」这条路径才能真正走通。

### ★ 改动 4（必须）：用我方的 `assistant.js` 覆盖新包那份

新包 `js/assistant.js` 是**没有任何接口调用的 mock 骨架**。
我方 `前端/SUFE-Knowledge-Galaxy/js/assistant.js` 已对接 `/api/graph/query`，直接覆盖即可
（`index.html` 第 828 行的 `<script src="js/assistant.js">` 位置不变，不用动）。

## 三、接入后怎么验证（10 分钟）

1. 起后端：`E:/python/python.exe -m uvicorn main:app --host 127.0.0.1 --port 8000`（根目录），
   等日志出现 6 行 `[preload] … 预热完成`（最后一行是 `v6`）。
2. 打开 `http://localhost:8000/index.html`，进知识星系页，确认画布正常出图。
3. 打开浏览器控制台，执行：
   ```js
   window.GalaxyEngine.state.graphId          // 期望 'v6'
   window.GalaxyEngine.state.nodes.length     // 期望 3661
   ```
4. 在助手问一句「什么是货币的流通手段职能？」：
   - Network 里 `/api/graph/query` 的请求体应含 `"graph_id":"v6"`；
   - 响应 `code` 为 0、`degraded` 为 false、`answer.related_nodes` 里是 `kp_*`；
   - 画布上对应微观点应出现脉冲高亮（约 3 秒）。
   - 参考耗时：首次约 8s（Agent 慢通道），关键词短句约 0.02s 走快通道。
5. 从课程星系点一个概念跳过来，确认能聚焦到对应节点（改动 3 生效）。

## 四、不建议的做法

- **不要用旧的 `js/galaxy.js` 去渲染 v6**：v6 的 `layer` 是 5 档
  （`domain/macro/meso/micro/explanation`），旧布局引擎按 3 档算环半径，会画错。
  要连后端就用新引擎，不要混搭。
- **不要把 4.7 MB 的原始 JSON 当作长期数据源**（除非放弃改动 2）：显示与 Agent 会变成两份数据，
  前端负责人一更新源文件、后端这边就静默过期。

## 五、已知限制（接入后依然存在，不是 bug）

1. **Agent 引用到 `kp_l4_*`「解释」节点时不会高亮**：新引擎的 `pulseNodes` / `focusOnNodes`
   只认 `level === 'micro'`（`knowledge-galaxy.js` 第 1525~1544 行），L4 节点走名称兜底也匹配不上
   （L4 的名字带「-解释」后缀）。共 1675 个 L4 节点。
2. **158 个 `kp_ext_*` 跨学科节点默认不显示**：引擎按 `is_external === true` 过滤
   （第 1254 行），只有切到 `viewMode: 'extend'` 才可见。
3. **页码为空**：v6 无 `page` 字段，节点详情里没有"教材第 N 页"。
4. **Agent 侧两处对旧数据集的硬编码**（`backend/src/`，Agent 层代码，未改）：
   v6 问答不做"同章兄弟节点"扩展、上下文里没有章级提示。
   详见 `文档/记录/v6图谱接入后端记录.md` 第四节第 3 条。
