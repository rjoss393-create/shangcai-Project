## 0. 一句话结论

新版 `layoutGalaxy()` 是**四层放射布局**（`domain → macro → meso → micro`），靠节点的 **`parent_id`**
串成树来确定"谁是根、谁在哪个扇区、哪条环带"。而**我方后端把层级放在 `extra.parents` / `extra.source_books` 里，
节点顶层没有 `domain` / `parent_id`**，于是：

- **`roots` 变成全部节点**（econ 2452 个）→ 全部挤在内环（半径 85px）→ 视口里就是**糊成一团**；
- 一次性挂 **22,796 个 SVG 元素**（其中 7718 个是关系标签）→ **卡**。

> 这不是渲染 bug，是**数据结构没对齐**。前端包自带的 `galaxy.json`（1911 节点 / 2896 边）带 `domain` + `parent_id`，
> 所以当初演示效果是正常的；换成后端数据就塌了。

## 2. 根因定位（代码级）

### 2.1 `js/galaxy.js:240-259` — `toNode()` 读不到层级

```js
        function toNode(raw) {
            return {
                id:            String(raw.id),
                label:         raw.name          ?? raw.label ?? '',
                type:          raw.level         ?? raw.layer ?? 'micro',
                domain:        raw.domain        ?? '',        // ← 后端没有顶层 domain → ''
                parent_id:     raw.parent_id     ?? null,      // ← 后端没有顶层 parent_id → null
                ...
```

`raw.domain` / `raw.parent_id` 是**前端包自带 `galaxy.json`** 的字段。我方后端节点的真实形状是：

```json
{
  "id": "concept_0010", "label": "并购基础知识", "type": "concept",
  "page": 11, "layer": "micro", "media": null,
  "extra": { "parents": ["section_0011"], "quality": "low", "source_books": ["并购与重组_知识图谱.json"] }
}
```

层级在 `extra` 里 → `parent_id` 恒为 `null`。

### 2.2 `js/galaxy.js:581-743` — `layoutGalaxy()` 把无父节点的都当根

```js
        state.nodes.forEach(n => {
            const pid = n.parent_id;
            if (pid && byId.has(pid)) { ...childrenOf... }
            else { roots.push(n); }        // ← 2452 个节点全进这里
        });
        ...
        const sectorAll = TWO_PI / roots.length;                       // 2452 分之一，几乎为 0
        rMacro = Math.max(rMacro, cnt * LAYOUT_SPACING.macro / sectorAll);
        ...
        roots.forEach((root, ri) => {
            const aMid = -Math.PI / 2 + sectorAll * (ri + 0.5);
            root.x = DOMAIN_R * Math.cos(aMid);                        // DOMAIN_R = 85
            root.y = DOMAIN_R * Math.sin(aMid);                        // → 2452 个点挤在半径 85 的圈上
```

`DOMAIN_R = 85` 只有 534px 周长，2452 个直径 13~25px 的圆放上去 → 完全叠死；
随后 `relaxCollisions()` 把它们摊开成一个半径约 300px 的球 → **就是你看到的"糊成一团"**。

## 3. 需要前端做的改动

### 改动 1（必做）：`toNode()` 回退读取后端层级字段

在 `js/galaxy.js` 第 240 行 `function toNode(raw) {` **之前**（即第 239 行那条注释之后）插入两个辅助函数：

```js
        // ★ 2026-09-20：后端把层级放在 extra 里（见《文档/协议/字段.md》），这里做回退读取。
        //   extra.parents      = 父节点 id 列表（数组，取第一个即可）
        //   extra.source_books = 来源书目（只有「经济综合」图有）
        function backendParent(raw) {
            const ps = raw && raw.extra && raw.extra.parents;
            return (ps && ps.length) ? String(ps[0]) : null;
        }
        function backendDomain(raw) {
            const sb = raw && raw.extra && raw.extra.source_books;
            return (sb && sb.length) ? String(sb[0]).replace(/_知识图谱\.json$/, '') : '';
        }
```

然后把 `toNode` 里的两行

```js
                domain:        raw.domain        ?? '',
                parent_id:     raw.parent_id     ?? null,
```

改为

```js
                domain:        raw.domain        ?? backendDomain(raw),
                parent_id:     raw.parent_id     ?? backendParent(raw),
```

> **注意**：保留 `raw.domain ??` 在前——前端包自带 `galaxy.json` 的字段仍然优先，
> 这样以后若恢复"本地 JSON 优先"也不会互相干扰。

### 改动 2（必做）：补「书 / 域」这一层根节点

**为什么必须补（实测对比）**：只做改动 1，`roots` 会从 2452 变成 **46 个"章"**，
而 `rMacro = max(300, 子节点数 × 92 / 扇区角)` 会随根数被放大：

| 指标 | 现状 | 只做改动 1（根=46 章） | 改动 1+2（根=书） |
|---|---|---|---|
| `roots` | 2452 | 46 | **4** |
| `_depth` 分布 | `{0:2452}` | `{0:46, 1:1427, 2:979}` | **`{0:4, 1:46, 2:1427, 3:979}`** |
| 节点中位半径 | 129 px | **141,444 px** | **1,905 px** |
| 整图包围盒 | 505 × 496 | **282,993 × 282,990** | **5,267 × 4,377** |
| 同格重叠节点数 | 2414 | 8 | **42** |

只做改动 1 会把图放大到**半径 14 万像素**，等于散到什么都看不见（元素被全裁掉，画面上几乎是空的）。
**补一层根是这套布局成立的前提，不能省。**

**插入位置**：`js/galaxy.js` 第 288 行 `state.visibleIds = new Set(...)` **之后**、
第 290 行 `const idSet = ...` 之前（必须在第 303 行 `layoutGalaxy()` 之前）。

```js
        // ★ 2026-09-20：补「书 / 域」这一层合成根节点。
        //   新版 layoutGalaxy() 是四层放射布局（domain → macro → meso → micro），
        //   它把「没有 parent_id 的节点」当根。后端数据顶层只有「章」，
        //   若直接当根 → roots 变成几十个，宏环半径按根数放大，整图散到看不见。
        //   补一层根后：econ 得到 4 个（4 本书），单本书图得到 1 个。
        const SYNTH_DOMAIN_PREFIX = '__domain__';
        const hasDomainLevel = state.nodes.some(n => n.type === 'domain');
        if (!hasDomainLevel) {
            const topNodes = state.nodes.filter(n => !n.parent_id);
            const groups = new Map();
            topNodes.forEach(n => {
                // 没有 source_books 的图（投资学 / 公司金融 / 国际投资学 / 并购与重组）
                // 全部归到同一个根，根名用后端给的图标题
                const key = n.domain || (data.title || '全部');
                if (!groups.has(key)) groups.set(key, []);
                groups.get(key).push(n);
            });
            const synth = [];
            groups.forEach((members, key) => {
                const id = SYNTH_DOMAIN_PREFIX + key;
                synth.push({
                    id, label: key, type: 'domain', domain: key,
                    parent_id: null, domains: [], courses: [],
                    description: '', media: null, tags: null, teaching_case: null,
                    quality: '', x: 0, y: 0, _visible: true, _synthetic: true
                });
                members.forEach(n => { n.parent_id = id; });
            });
            state.nodes = [...synth, ...state.nodes];
            // ★ 必须同步 visibleIds：render() 会用 !visibleIds.has(id) 给节点加 .faded
            synth.forEach(n => state.visibleIds.add(n.id));
        }
```

**三个容易踩的点**：

1. **必须同步 `state.visibleIds`**（§4.2 有依据）。忘了就会出现"4 个书节点是灰的"。
2. **不要重复合成**：前端包自带 `galaxy.json` 已经有 `level: 'domain'` 的节点，所以用
   `hasDomainLevel` 判一下再合成。
3. **`data.title` 可直接用**：`/api/graph/load` 返回里有，实测
   `econ → 经济综合 / invest → 投资学 / corp_fin → 公司金融 / intl_inv → 国际投资学 / ma → 并购与重组`。

### 改动 3（可选）：让合成节点点击时不请求后端

合成节点不在后端图谱里，点它会 `POST /api/graph/click` 带 `node_id: "__domain__经济综合"`。
**实测后端对未知 `node_id` 是容错的**（返回 `code:0` + 一条"聚焦自身"的 action），所以**不改也不会报错**。
若想让交互更干净，可在 `handleNodeClick`（第 1348 行）开头加：

```js
        // 合成节点（书/域层）不在后端图谱里 → 本地聚焦即可
        if (String(nodeId).startsWith('__domain__')) { localFocusNode(nodeId); return; }
```

### 改动 4（建议）：削减常驻 DOM——关系标签不要一次全建

`js/galaxy.js:509-511` 把**全部** `activeEdges` 都 append 成 `<text class="g-link-label">`，
再靠 CSS `.hidden` / `opacity: 0` 藏起来。**econ 有 7718 条边 → 7718 个常驻 `<text>`**，
占 22,796 个 SVG 元素的 **34%**，是"卡"的最大单一来源。

**建议**：把 data join 的输入先按"当前是否需要"过滤，而不是全建后靠 CSS 藏：

```js
        // 只有「高倍微观层」或「两端高亮 / 位于路径上」才真正创建标签节点
        const labelsNeeded = activeEdges.filter(e => {
            const s = srcId(e), t = tgtId(e);
            if (lvl === 'micro') return true;
            const bothHi = state.highlightedIds.has(s) && state.highlightedIds.has(t);
            const onPath = state.activePath && isPathEdge(s, t);
            return !!(bothHi || onPath);
        });
        const lls = gLinkLabels.selectAll('.g-link-label').data(labelsNeeded, edgeKey);
```

`highlightedIds` 是在 `focusOnNodes` / `handleResponse` 里写入的（第 1341 / 1461 / 1534 行），
之后都会走 `render()`，所以"高亮后才需要标签"这一路径成立。
**但这一处请你们按自己的渲染时机复核一遍**：我确认了高亮会触发重渲染，
没确认的是"逐节点 hover 是否也依赖已存在的标签节点"（`.g-link-label.hidden` 在 `css/style.css:1750`）。
若 hover 依赖常驻节点，改成"hover 时单独 append 一个临时标签"更稳。

预期收益：econ 的 SVG 元素从 **22,796 → 约 15,000**。

## 6. 回归红线（改的时候别碰）

这几处是 2026-09-15 ~ 09-20 已修好的问题，改布局时容易顺手带掉：

1. **`/api/graph/click` 与 `/api/graph/query` 的 `graph_id`**（第 1369 / 1664 行）
   —— 后端 `service._require()` 要求必填，缺了会 `code:500「graph_id 必填」`，点节点和问答整条链路失效。
2. **`state.graphId` 别名**（第 119 行 `Object.defineProperty(state, 'graphId', ...)`，整段 113-125 行）
   —— `js/assistant.js` 读的是旧名 `state.graphId`，删了它问答会固定只查经济综合图。
3. **`toNode()` 里的 `label: raw.name ?? raw.label`、`type: raw.level ?? raw.layer`**
   —— 双端字段兼容，删了会标签全空 + 所有节点被判成 micro。
4. **`quality=low` 标签默认隐藏**（`qualityOf()` + `.low-q` 类 + `css/style.css` 的 `.g-label.low-q` 规则）
   —— econ 有 672 个 low 节点，全显会糊。
5. **`:not(.faded)` 两条 zoom-micro 规则** 与 **标签字号补偿（宏观 30px / 中观 20px）**。
6. **`.bg-label` 深色文字**（`#222` / `#111`）—— 改回浅色在白底上看不见。

## 8. 附：可以协商由后端承担的部分

上面改动 1 里的两个辅助函数，本质是"把后端字段摊平"。如果你们不想在前端做这层适配，
**我们可以改由后端在节点顶层直接输出 `parent_id` 和 `domain`**（纯新增字段，不动现有字段），
你们就只需要做改动 2（补根节点）和第 4/5 项。

需要你们定一下哪种分工更合适：
- **A. 前端全做**（改动 1+2 都在 `galaxy.js`）：不需要我们改后端，不涉及 API 契约变动；
- **B. 后端摊平字段 + 前端补根**：后端 API 新增两个顶层字段，`extra` 保留不动，向后兼容。

我们倾向 **A**（改动量小、只动一个文件、不碰 API 契约和 Agent 层的预载逻辑），但听你们的。
