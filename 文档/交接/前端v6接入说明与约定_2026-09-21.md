## 二、为什么新引擎要接后端（这次的核心）

页面上原本有两条互不相干的链路：

| | 改动前 | 改动后 |
|---|---|---|
| **画布显示** | `fetch('data/galaxy_v6_clustered.json')` 读本地文件，节点 `kp_*` | `POST /api/graph/load {graph_id:'v6'}`，同一批 `kp_*` |
| **助手问答** | `assistant.js` 读 `state.graphId` → 取不到，兜底 `'econ'` → 后端返 `concept_*` | 同一个 `graph_id:'v6'` |

改动前：答案里引用的 `concept_*` 节点在 v6 画布上不存在 → 高亮全部失效，答案讲的也是另一张图。
改动后：两侧同源，`kp_*` 能直接命中画布节点。

## 三、`js/knowledge-galaxy.js` 的 4 处改动（对照后端契约）

### 1) 数据源改走后端（原第 25 行常量 + `load()` 函数）

```js
/* 原 */
const DATA_URL = 'data/galaxy_v6_clustered.json';
...
loadPromise = fetch(DATA_URL)
    .then(r => { ... return r.json(); })
    .then(data => { state.data = data; state.idx = buildIndex(data); ... });
```
```js
/* 现 */
const GRAPH_ID = 'v6';              /* 后端 controller/graph_ids.py 里登记的图谱 */
const API_BASE = '';               /* 与页面同源；页面不由后端托管时写 'http://localhost:8000' */
const DATA_URL = 'data/galaxy_v6_clustered.json';   /* 保留作参考，已不再使用 */
...
loadPromise = fetch(API_BASE + '/api/graph/load', {
        method:  'POST',
        headers: { 'Content-Type': 'application/json' },
        body:    JSON.stringify({ graph_id: GRAPH_ID })
    })
    .then(r => { if (!r.ok) throw new Error('HTTP ' + r.status); return r.json(); })
    .then(resp => {
        if (!resp || resp.code !== 0) throw new Error((resp && resp.message) || '接口返回异常');
        const d = resp.data || {};
        /* 后端契约 {id,label,page,layer,media,extra} -> v6 引擎原字段名 */
        const data = {
            nodes: (d.nodes || []).map(n =>
                Object.assign({}, n.extra || {}, { id: n.id, name: n.label })),
            edges: (d.edges || []).map(e =>
                Object.assign({}, e.extra || {}, {
                    source: e.source, target: e.target, relation: e.relation
                }))
        };
        state.data = data;
        state.idx = buildIndex(data);
        ...   /* 以下十余行一个字没改 */
```

> **为什么适配只要一行**：后端转换脚本把 v6 的原始字段名（`level` / `parent_id` / `content` /
> `cluster_id` / `cluster_name` / `domain` / `tags` / `difficulty` / `importance` / `is_external` …）
> **原样保留在 `extra` 里**，所以 `Object.assign({}, n.extra, {id, name})` 就能把节点还原成
> v6 引擎认识的形状。引擎完全不用改。

### 2) `state` 加 `graphId`（原第 62 行附近）

```js
        currentGraphId: 'econ',   /* 兼容旧引擎契约（课程星系移植时读写） */
        graphId: 'v6',            /* ★ 助手提问用；assistant.js 读 state.graphId */
```

> **不要**写成 `Object.defineProperty(state,'graphId',{get:()=>state.currentGraphId})`。
> 老引擎（`js/galaxy.js` 第 119~124 行）是那么写的，但新架构下画布**永远显示 v6**，
> 而 `course-galaxy.js`（第 551 行）跳转时会 `switchGraph('econ')` 把 `currentGraphId` 改成 `econ`
> —— 用别名会让助手一旦被课程星系"带偏"就再也问不到 v6。

### 3) 补 `state.nodes` 别名

```js
    /* 兼容旧引擎的 state.nodes：course-galaxy.js 用它按 id 找节点 */
    Object.defineProperty(state, 'nodes', {
        get() { return (state.data && state.data.nodes) || []; },
        enumerable: true, configurable: true
    });
```

### 4) 补 `GalaxyEngine.clickNode`（含层级路由）

```js
        clickNode(idOrName) {
            const idx = state.idx;
            const n = idx && idx.byId.get(idOrName);
            if (n) {
                if (n.level === 'macro') enterMacro(n.id);
                else if (n.level === 'meso') enterMeso(n.id);
                else if (n.level === 'micro') jumpToMicro(n.id);
                else if (n.level === 'explanation') jumpToMicro(n.parent_id || n.id);
                else goOverview();
                return;
            }
            this.selectNode(idOrName);
        },
```

新引擎只导出 `selectNode`（且只认 `micro` 层），而 `course-galaxy.js` 第 542 行传进来的是
`kp_macro_*`（学科节点），所以必须按层级分流，否则「课程星系点概念 → 跳知识星系」只会 toast
「未找到对应概念节点」。

## 五、★ 对接约定（前端以后更新请照这个来）

1. **知识星系的数据必须来自后端**，`graph_id = 'v6'`，走 `POST /api/graph/load`。
   不要再让引擎 `fetch` 本地 JSON —— 否则前端和后端各存一份 v6 数据，谁更新了都会静默不同步。
2. **`state.graphId` 必须等于"画布上此刻真正显示的那张图"**，且**不能**做成 `currentGraphId` 的别名。
   谁改画布显示内容，谁负责同步 `graphId`。
3. **`window.GalaxyEngine` 的对外壳要保住向后兼容**：`clickNode` / `selectNode` / `pulseNodes` /
   `focusOnNodes` / `switchGraph` / `goMacro` / `state.nodes` / `state.graphId`。
   知识助手 `assistant.js` 和课程星系 `course-galaxy.js` 都靠这层壳联动；换引擎内部实现可以，壳别拆。
4. **节点字段契约**：后端给的是 `{id, label, type, page, layer, media, extra}`，
   层级信息在 `extra.parents`（数组）与 `extra.level` 里。
   前端适配写 `Object.assign({}, n.extra, { id: n.id, name: n.label })` 即可拿到
   `level` / `parent_id` / `content` / `cluster_id` 等全部原字段。
   若以后换成别的数据源，**`level` 和 `parent_id` 这两个字段名必须保留**（引擎的分层树靠它们）。
5. **替换某个板块的 HTML 前，先清点该板块的 DOM 被哪些 js 引用**。
   本次只换知识星系板块，是因为核对过：旧标记（`galaxyTabs`/`galaxyZoomLevel`/`galaxyNodePopup`/
   `galaxyStars`/`galaxyToast`/`galaxyImmersiveExit`/`galaxyTooltip`）**只被 `galaxy.js` 自己引用**，
   `main.js`、`assistant.js`、`course-galaxy.js` 都不依赖；唯一的外部引用是 `assistant.js` 用了
   `#galaxyStage`，而新标记里保留了同名 id。
6. **不要回退既有集成**：`main.js`（七色配色 / 昼夜主题 `sufe_theme` / PDF `#page=1`）、
   `auth.js`（真登录，`USE_MOCK:false`）、`assistant.js`（已对接 `/api/graph/query`）。
   交付新前端包时请以这几个文件的我方版本为准，或先说明改了哪里。
7. **数据结构变了要同步后端**：v6 图谱数据由 `scripts/import_v6_galaxy.py` 从
   `data/layered/v6_layered.json` 提供给后端；若前端要改节点/边的字段，先提出来，由后端侧同步转换脚本，
   不要单方面在前端"补字段"。换数据后需清 `backend/cache/v6_all-MiniLM-L6-v2/` 再重启后端。
8. **`graph_id` 的取值表是共享契约**：`ma / corp_fin / intl_inv / invest / econ / v6`，
   定义在 `backend/controller/graph_ids.py`。新增图谱只加行、不改旧值。

## 六、已知限制（不是 bug，暂不在本次修）

1. **Agent 答案引用 `kp_l4_*`「解释」节点时不会高亮**：引擎的 `pulseNodes` / `focusOnNodes` / `selectNode`
   只认 `level === 'micro'`（`knowledge-galaxy.js` 第 1546 行起），L4 名字带「-解释」后缀，
   名称兜底也匹配不上。共 1675 个 L4 节点。本次实测答案里 `kp_l4_0002 流通手段` 可点但无反应，
   `kp_micro_0002 货币职能` 正常。
2. **158 个 `kp_ext_*` 跨学科节点默认不显示**（`is_external` 过滤），切到「扩展视图」才可见。
3. **v6 没有页码**，节点详情里没有"教材第 N 页"。
4. **Agent 层两处对旧数据集的硬编码**（`backend/src/`，Agent 层同学的代码，未动）：
   v6 问答不做"同章兄弟节点"扩展、上下文里没有章级提示。
   见 `文档/记录/v6图谱接入后端记录.md` 第四节第 3 条。
5. **新包还有这些没合并**（要不要合由前端负责人定）：
   课程星系板块的「图谱切换」入口（新包把它从知识星系挪到了课程星系）、
   市场行情/新闻板块的一行式重构、`course-galaxy.js` 新版的 810 行实现。
   现状是我方课程星系 + 我方 `course-galaxy.js`（694 行），能正常跳转与聚焦。
