## 四、已知代价与遗留（不在本次范围）

1. **页码全丢**：v6 无 `page` 字段 → "答案定位到教材第 N 页"对 v6 图谱不可用。
   补救思路（未验证）：用节点名与既有 `concept_*` 节点做名字匹配回填页码，匹配率需先统计。
2. **前端还未接入**：页面仍走旧 `galaxy.js` + 既有 5 个图谱；`v6` 目前只能通过 API 访问。
   下一步（需前端配合）是把 `knowledge-galaxy.js` 的取数从 `fetch('data/galaxy_v6_clustered.json')`
   改为带 `graph_id:'v6'` 调 `/api/graph/{load,click,query}`，否则前端展示 v6 图而 Agent 拿不到
   `graph_id`，答案高亮会全部对不上。
3. **Agent 层有两处对旧数据集的硬编码**（`backend/src/`，Agent 层代码，本次未动）：
   - `llm_navigator.py::fast_retrieve_answer` 节点扩展处 `if "concept" in child_node_id or "formula" in child_node_id:`
     → v6 的 `kp_*` id 不匹配，**v6 问答不会做"同章兄弟节点"扩展**，只用 5 个种子节点作答。
   - `path_rag.py::_get_parent_chapter` 靠节点标签里是否含「章/节/section/chapter」反查所属章节
     → v6 标签是知识点名，恒返回空，**上下文里没有"（来自：xx）"的章级提示**。
   两者都不影响 Agent 可用，只影响答案丰富度。用户当前表示**暂不优化**。
4. v6 有 **158 个 `kp_ext_*` 扩展节点在源数据里就没有 `parent_id`**
   （连同 3 个 domain 节点，共 161 个"根"）。转换脚本原样保留，没有替它造父节点。
